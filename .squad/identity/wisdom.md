# Team Wisdom

Reusable patterns and heuristics learned through work. NOT transcripts — each entry is a distilled, actionable insight.

## Patterns

**Pattern:** Spec-kit sequence is non-negotiable even for PoCs. **Context:** Skipping specs to "save time" always costs more in rework than writing a quick spec up front. The sequence is: constitution → specify → plan → tasks → implement. No shortcuts.

**Pattern:** PoC definition of done = it runs + happy path works. **Context:** Anything beyond this is gold-plating for a proof-of-concept. Ship it and iterate if it has legs.

**Pattern:** Match model cost to task criticality. **Context:** Expensive models (Opus) for specs/planning where mistakes cascade; mid-tier (Sonnet) for implementation; cheap (Haiku) for admin and smoke testing.
